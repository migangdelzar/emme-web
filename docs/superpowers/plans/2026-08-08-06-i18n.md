# Internationalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Provide typed shared translations, feature namespaces, locale selection, and deterministic formatters through `@emme/i18n`.

**Architecture:** Shared common/navigation/error messages stay in i18n; feature messages stay under each feature; apps register namespaces through the composition root.

**Tech Stack:** React 19, TypeScript, Vitest, existing locale catalogs and formatter utilities.

## Global Constraints

- Keep `es-MX` and `en-US` parity.
- Translation keys are typed and validated.
- Feature code does not import app-local translation modules.

## Files

- Modify: `packages/i18n/src/index.ts`, provider, locale, translation, formatter, validation, and catalog files.
- Create: `packages/i18n/src/locales/en/`, `packages/i18n/src/locales/es/`, feature namespace registration modules, and boundary tests.
- Test: existing formatter/provider/catalog tests plus `src/__tests__/translation-boundary.test.ts`.

### Task 1: Typed catalogs and namespace registration

- [ ] **Step 1:** Write a failing parity test that reports a missing key in either locale.
- [ ] **Step 2:** Implement typed `TranslationKey`, catalog loading, namespace registration, fallback locale, and missing-key behavior.
- [ ] **Step 3:** Run `bun run --filter @emme/i18n validate`; expected result is PASS.

### Task 2: Providers and formatters

- [ ] **Step 1:** Write tests for locale selection, fallback, currency, date, time, relative time, and validation-message formatting.
- [ ] **Step 2:** Implement providers/hooks and formatter functions with explicit locale/time-zone inputs.
- [ ] **Step 3:** Run `bun run --filter @emme/i18n test` and typecheck; expected result is PASS.

### Task 3: Feature test provider and exports

- [ ] **Step 1:** Write a test proving a feature namespace can be supplied without mutating global catalogs.
- [ ] **Step 2:** Implement `I18nTestProvider` and public exports; move reusable app translation composition into the package.
- [ ] **Step 3:** Run `bun run i18n:check`; expected result is PASS.

### Task 4: Commit


## Definition of Done

- [ ] Locale catalogs have parity and validation.
- [ ] Feature namespaces remain feature-owned.
- [ ] All formatters have boundary and locale tests.
