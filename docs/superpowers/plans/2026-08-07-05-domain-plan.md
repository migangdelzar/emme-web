# @emme/domain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task.

**Goal:** Build the pure business model and rules reused by salon, client, and platform workflows.

**Architecture:** The package is framework-free and transport-free. It owns business language, invariants, statuses, and value behavior; it does not know API DTOs or tenant storage.

**Tech Stack:** TypeScript, Vitest, Bun.

## Global Constraints

- No React, API, HTTP, storage, browser, React Query, or infrastructure imports.
- Do not copy API DTOs into domain files without deliberate domain modeling.
- Use explicit business names and deterministic date/time inputs.
- Every rule has edge-case tests before implementation.

## Current inventory

- `packages/domain/src/appointments/*` contains appointment status/rules.
- `packages/domain/src/clients/*` contains client types/rules.
- `apps/emme-salon-app/src/features/*/domain` contains app-facing aliases and service rules.
- `packages/api/src/appointments/api.ts`, `clients/api.ts`, and `services/api.ts` are transport models and must remain outside domain.
