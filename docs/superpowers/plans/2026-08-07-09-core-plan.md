# Core Package Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task.

**Goal:** Make `@emme/core` the reusable runtime layer for authentication, tenancy, permissions, configuration, errors, and provider composition.
**Architecture:** Shared application runtime contracts and React providers; concrete browser/network behavior is injected from `@emme/infrastructure`.
**Tech Stack:** TypeScript, React, Bun workspaces, Vitest, Testing Library, `@emme/api`, `@emme/domain` only where a shared type is required.

## Global Constraints

- Core does not instantiate fetch clients, storage implementations, analytics SDKs, or API repositories.
- Auth and tenant providers expose explicit loading, unauthenticated, unavailable, and ready states.
- Permission checks improve UI behavior but do not replace backend authorization.
- Configuration parsing validates required environment values at the boundary and produces stable configuration errors.
- Tests are colocated; package-level provider composition tests use `src/__tests__/`.

## 2. Ordered Tasks

### Task 1: Define auth and tenancy protocols

**Files:** `packages/core/src/auth/**`, `packages/core/src/tenancy/**`, colocated tests.

Write failing tests for provider states, current-user access, tenant selection, tenant switching, and reset on logout. Define injectable interfaces for session access, tenant resolution, and tenant selection. Implement providers with explicit dependency props or factory configuration rather than importing infrastructure singletons.

Preserve the current salon session and tenant resolver behavior while normalizing naming to kebab-case files and typed context values.

### Task 2: Implement access-control primitives

**Files:** `packages/core/src/access-control/**`, existing permission tests migrated from current locations.

Write tests for role-to-permission expansion, direct permission checks, policy predicates, missing permissions, and guard rendering. Implement `Permission`, `Role`, `UserPermissions`, `can`, `usePermission`, and `PermissionGuard` with stable public types. Ensure a missing permission fails closed.

### Task 3: Add runtime, configuration, and error contracts

**Files:** `packages/core/src/runtime/**`, `configuration/**`, `errors/**`, `types/**`.

Write tests for provider composition, invalid environment/configuration, API context availability, and error classification. Implement runtime providers that accept already-created API and infrastructure dependencies. Error classes must carry safe user-facing codes while preserving a cause for logging.

### Task 4: Migrate salon app providers and auth/config modules

**Files:** `apps/emme-salon-app/src/app/AppProviders.tsx`, `src/app/auth/**`, `src/app/config/**`, related tests.

Replace duplicated app implementations with `@emme/core` providers and app-specific composition configuration. Keep route guards and tenant-selection UI in the app. Inject token/session and API implementations from `@emme/infrastructure`.

### Task 5: Verify provider and dependency boundaries

**Files:** `packages/core/src/__tests__/provider-composition.test.tsx`, package exports, app tests.

Test the provider tree with test-support fakes, then scan core imports to ensure concrete HTTP, storage, and analytics implementations are absent. Verify all public exports through `@emme/core`.
