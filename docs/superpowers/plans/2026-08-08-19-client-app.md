# Client App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Build the client-facing app shell and workflows for `FR-WC001`–`FR-WC019` using shared feature contracts and backend-authoritative capabilities.

**Architecture:** `apps/client-app` owns client routes, pages, forms, chat/booking workflows, and client-specific navigation. Shared appointments, catalog, customers, payments, communications, integrations, core, UI, i18n, API, and infrastructure remain reusable packages.

**Tech Stack:** React 19, Vite, React Router, TanStack Query, Testing Library, Vitest, Playwright.

## Global Constraints

- Customer tenant context is resolved by core/API contracts and cannot be selected from arbitrary input.
- Backend authorization and booking/payment rules remain authoritative.
- Social identity is rendered only when the backend capability exists; the UI reports unavailable capability safely.
- WhatsApp/web chat/AI/media providers are mocked in unit tests.
