# API Package Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task.

**Goal:** Make `@emme/api` the typed backend SDK and contract boundary shared by all three apps without embedding HTTP, React, or browser behavior.
**Architecture:** API ports plus capability-oriented DTOs, request types, route definitions, mappers, and SDK factories. Concrete transport is supplied by `@emme/infrastructure`.
**Tech Stack:** TypeScript, Bun workspaces, Vitest, current generated API/client typings in `packages/api-client` and `packages/contracts`.

## Global Constraints

- Preserve the existing backend routes, request payloads, response shapes, and generated contract types.
- The public package name is `@emme/api`; no new consumer may use `api-client` naming.
- API modules may depend on contracts and ports, but not on React, React Query, localStorage, or a concrete `fetch` implementation.
- DTO-to-domain conversion belongs in an explicit mapper or infrastructure adapter, never in UI components.
- Tests use injected fake `HttpClient` implementations.

## 2. Ordered Tasks

### Task 1: Establish contract and transport-port boundaries

**Files:** `packages/api/src/contracts/**`, `packages/api/src/ports/http-client.ts`, `packages/api/src/ports/api-context.ts`, colocated tests.

Write failing type-level and runtime tests for common pagination, request context, error envelopes, and the current HTTP port. Confirm behavior for query parameters, JSON bodies, empty responses, status metadata, authentication context, and tenant context. Align imports with the extracted contract library and update package metadata to expose the conventional `api` package name.

Use an interface such as:

```ts
export interface HttpClient {
  get<T>(path: string, options?: RequestOptions): Promise<T>;
  post<T>(path: string, body?: unknown, options?: RequestOptions): Promise<T>;
  patch<T>(path: string, body?: unknown, options?: RequestOptions): Promise<T>;
  delete<T>(path: string, options?: RequestOptions): Promise<T>;
}
```

The exact options type must preserve the current implementation’s supported headers, query, and tenant fields.

### Task 2: Migrate capability SDK modules

**Files:** `packages/api/src/auth/**`, `tenants/**`, `clients/**`, `appointments/**`, `services/**`, `staff/**`, `payments/**`, `integrations/**`.

For each capability, write or update tests against a recording fake HTTP client first. Then move current route and payload behavior into plural capability modules named `*.api.ts`. Keep methods typed with DTO/request types from `contracts`. Verify list, detail, create, update, delete/status, booking/availability, authentication, and integration operations that currently exist.

Where the backend and domain naming differ, return DTOs from `@emme/api` and perform domain mapping in the infrastructure adapter used by application ports. Do not make capability APIs import domain rules.

### Task 3: Add SDK factory and stable public exports

**Files:** `packages/api/src/create-api.ts`, capability `index.ts` files, `packages/api/src/index.ts`, `packages/api/src/__tests__/capability-apis.test.ts`.

Create `createApi(httpClient, context?)` as the composition entry point. It returns capability clients with no hidden singleton state. Add package-level contract tests that instantiate the SDK with a fake transport and assert route/method/body/query behavior across capabilities.

Export only public contracts, ports, capability API factories, and `createApi`. Keep test providers under a test-only export or move them to `@emme/test-support`.

### Task 4: Migrate consumers and remove API duplicates

**Files:** `apps/emme-salon-app/src/api/**`, feature API/query files, package manifests, tsconfig path aliases.

Replace direct imports from old `api-client` or app-local REST clients with `@emme/api` through infrastructure composition. Preserve app query key semantics while moving network calls behind package boundaries. Remove duplicates only after import scans and tests confirm no remaining consumers.
